Context

Why an existing project?

Building with AI from scratch is easy. Working with an existing codebase? That's the real challenge — and that's exactly what our day-to-day looks like.

Starting from scratch 😌

  • ✓ Blank canvas, your rules
  • ✓ No existing patterns to respect
  • ✓ AI can invent architecture freely
  • ✓ Great for demos and tutorials
  • ✓ No hidden tech debt

Real existing project 😅

  • ! Architecture to understand first
  • ! Coding conventions already set
  • ! Real dependencies & constraints
  • ! Domain knowledge required
  • ! This is what we actually do at work

Ghostfolio is a real open-source wealth management platform — Angular + NestJS + Nx. Big enough to be interesting, structured enough to learn from.

OpenCode

Meet OpenCode

An AI-powered coding agent that lives in your terminal — governed by the repository itself.

Why it matters

Instead of everyone writing loose prompts in a chat window, the team defines how to work with AI in versioned files — reviewed like code. The workflow becomes repeatable, traceable, and controllable. Commands, agents, skills, and MCPs live in the repo alongside the code.

Command
how to work
Agent
who works
Skill
what to know
MCP
what data to use

Per-agent permissions are real controls — the AI literally can't access files outside its allowed scope. This protects secrets, real data, and financial-safety boundaries.

Setup

Handy scripts

All scripts live in ./scripts/ — Windows folks, use the .ps1 equivalents.

1 · Start
./scripts/start.sh
Starts Ghostfolio via Docker → http://localhost:3333
2 · Check status
./scripts/check.sh
Verifies Ghostfolio is up and all services are running
3 · Seed demo data
./scripts/seed-workshop-data.sh
Creates 3 demo accounts with ~54 activities. Needs your security token.
4 · Verify MCP
./scripts/check-demo-mcp.sh
Checks MCP is wired. Works without Ghostfolio running (reads CSV files).
5 · Rebuild (only if you change app code under apps/)
./scripts/rebuild.sh
OpenCode config and MCP edits don't need this — only actual Ghostfolio code changes do.
Concept 1 / 4
01

Command

Repeatable workflows
What it is

Prompt templates invoked with /name. They standardise recurring tasks like investigate, plan, implement, and review.

Use case

Everyone uses the same approach — no improvised prompts, no guesswork. Versioned in the repo like any other file.

Location: .opencode/commands/<name>.md
Examples
/workshop-inspect-architecture <topic>
/workshop-plan-frontend-card
/workshop-plan-backend-card
/workshop-plan-mcp-card
/workshop-implement-small-product-slice
/workshop-review-financial-safety
/workshop-prepare-team-handoff
Concept 2 / 4
02

Skill

Reusable knowledge
What it is

Project best-practice manuals loaded on demand. They prevent the agent from reinventing patterns the codebase already has.

Use case

Carry domain knowledge about Ghostfolio's structure, NestJS conventions, Angular Nx patterns — so the AI doesn't guess or hallucinate.

Location: .opencode/skills/<name>/SKILL.md
Examples
ghostfolio-domain-analysis
nestjs-api-development
angular-nx-development
financial-safety-review

Skills are loaded only when the task needs them — no wasted context, no token bloat.

Concept 3 / 4
03

Agent

Specialists with permissions
What it is

Role-specific workers with their own system prompt and file permissions. A backend agent can edit backend code; a safety reviewer stays read-only.

Use case

Separation of concerns in AI workflows. Each agent knows its domain and can't go outside its lane. Governance is baked in.

Location: .opencode/agents/<name>.md + AGENTS.md
Examples
backend-nestjs-agent
frontend-angular-agent
financial-safety-reviewer
workshop-facilitator-agent

Permissions are real — the AI literally cannot access files outside its allowed scope.

Concept 4 / 4
04

MCP Model Context Protocol

Governed data access
What it is

Standard connectors that expose tools or data to OpenCode. Our workshop MCP gives read-only access to the demo portfolio data.

Use case

Instead of copy-pasting data into a chat and hoping the AI doesn't hallucinate the numbers — MCPs give structured, read-only access to actual data.

Config: opencode.json  ·  Code: tools/mcp/ghostfolio-demo-data-mcp/
Exposed tools
get_demo_portfolio_summary
detect_demo_anomalies
get_concentration_signals

The MCP works even without Ghostfolio running — it reads CSV files directly from the repo.
