# Reference Implementation — Portfolio Insights Demo

What was actually implemented in the solutions branch, what was intentionally left out, and how to test it.

## Option chosen and why

Among the three options proposed (backend-only, backend+frontend, MCP-only), the solutions branch implements
**Option 3: MCP-only + command + documentation**, as the functional happy path reference.

**Why it is the most robust and least invasive:**
- **It does not touch any functional Ghostfolio code** (`apps/api`, `apps/client`, `prisma/`), so it **cannot break** the
  build or the local Docker startup.
- It is **read-only** over demo data in CSV → reproducible and stable on Mac/Windows.
- It still demonstrates the complete end-to-end agentic cycle, because the MCP **is** real product tooling
  (portfolio data exposed to agents in a governed way).

The **frontend (FE-*)** and **backend (BE-*)** cards are delivered as **technical plans** generated by the
planning commands (`/workshop-plan-frontend-card`, `/workshop-plan-backend-card`). This is consistent with the
workshop philosophy ("research and planning first") and keeps the build intact. A team that wants to
can implement their plan as a minimal change, delegating to the specialist agent and after human review.

## What was implemented

1. **Local read-only MCP `ghostfolio-demo-data`** (`tools/mcp/ghostfolio-demo-data-mcp/`):
   - stdio JSON-RPC 2.0 server **with no dependencies** (`src/index.mjs`).
   - Read-only data layer (`src/data.mjs`) that **reuses** the CSV parser from `tools/workshop/lib/workshop-data.mjs`.
   - 7 tools: `list_demo_accounts`, `get_demo_portfolio_summary`, `list_demo_activities`, `detect_demo_anomalies`,
     `get_account_summary`, `get_symbol_exposure`, `get_recent_activities`.
   - Smoke test (`src/smoke-test.mjs`) that validates the handshake and data.
2. **Registration in `opencode.json`** of the MCP as a local server.
3. **Command `/workshop-analyze-demo-portfolio`** + agent `portfolio-domain-agent` that consume the MCP to produce
   descriptive insights.
4. **Safety gate**: command `/workshop-review-financial-safety` + agent `financial-safety-reviewer` + skill.
5. **Scripts** `scripts/start-demo-mcp.*` and `scripts/check-demo-mcp.*` (Mac/Windows).
6. All **workshop documentation** in `docs/workshop/`.

### Deterministic insights produced by the MCP (real dataset figures)

- **Concentration by account** (nominal cost share per symbol within the account):
  - *Trade Republic Growth*: AAPL 26.2%, MSFT 21.8%, NVDA 19.7%, ASML.AS 14.8%, GOOGL 12.4%, AMZN 5.1% (top-3 = 67.7%).
  - *Crypto Exchange*: BTC 60.8%, ETH 39.2%.
  - *MyInvestor Core ETF*: VWCE.DE 39.5% and a more diversified distribution (S&P500, EM, bonds, Europe, small cap).
- **Anomalies** (from the anomalies CSV, deterministic detection, does not use labels): 5 findings →
  `exact-duplicate`, `high-fee`, `currency-mismatch`, `price-outlier`, `oversell-risk`. On the clean dataset: ~0.

## What was intentionally left out

- **No real LLM**: the insights are deterministic calculations. The epic is called "Assistant" but in this phase there is no
  model generation. (Ghostfolio already ships its own `endpoints/ai/`; we do not touch it.)
- **No changes to `apps/`**: no real endpoint or component was added (they are delivered as plans).
- **No PostgreSQL access** from the MCP: the source is CSV (more reproducible). Documented as a limitation.
- **No currency conversion or current market prices**: we work with "nominal invested cost".

## How to test it

### 1. Isolated MCP (does not require Ghostfolio to be running)

```bash
# Mac/Linux
./scripts/check-demo-mcp.sh
# Windows
.\scripts\check-demo-mcp.ps1
```
Expected: 7 checks in green and `✅ MCP ghostfolio-demo-data OK`.

Manual tool call:
```bash
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"cli","version":"1.0.0"}}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"detect_demo_anomalies","arguments":{"source":"anomalies"}}}' \
  | node tools/mcp/ghostfolio-demo-data-mcp/src/index.mjs 2>/dev/null
```

### 2. Full cycle in OpenCode (happy path)

1. (Optional) Start Ghostfolio and seed data: `./scripts/start.sh` + `./scripts/seed-workshop-data.sh`.
   *Note:* the MCP reads CSV, so the insights demo works even if Ghostfolio is not running.
2. Open OpenCode at the repo root. It should detect the MCP `ghostfolio-demo-data` and the `/workshop-*` commands.
3. Run `/workshop-analyze-demo-portfolio` → summary with the figures above.
4. Run `/workshop-review-financial-safety docs/workshop/generated/INT-01-portfolio-insights.md`
   (or paste the text) → PASS verdict.

See detailed steps in `solution-runbook.md`.

## Security

`.env`, `prisma/schema.prisma`, `docker/`, and `nx.json` were not modified. No real data was touched. The MCP is
strictly read-only. No output recommends buying/selling or predicts prices.
