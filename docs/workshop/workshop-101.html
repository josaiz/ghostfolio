1
The north star
Repeat this often

We are not asking AI for code. We are building an agentic development system to implement a real product improvement.

Commands, agents, skills, and MCPs are the means. The goal is a useful Ghostfolio feature delivered in a governed, repeatable, reviewable way. Every card must have a functional product objective and must create, improve, or use at least one OpenCode component.

Anchor idea

Command = how to work. Agent = who works. Skill = what to know. MCP = what data to use.

2
What you will build

The shared epic is Portfolio Insights Assistant. It summarises the demo portfolio, detects concentration by account and symbol, identifies simple deterministic anomalies, displays educational insights, and avoids personalised financial advice.

Demo portfolio summary
Descriptive insight

Show account totals, holdings, cost, and concentration using the workshop demo data.

Concentration signals
Account and symbol view

Identify where nominal cost is concentrated without saying what to buy or sell.

Anomaly detection
Deterministic heuristics

Flag examples such as duplicates, high fees, currency mismatches, price outliers, and oversell risk.

Safe explanation
Governed language

Review visible copy so it remains descriptive and educational, not personalised financial advice.

3
OpenCode model

OpenCode is an AI-powered coding agent that lives in the terminal, but the important part for this workshop is that it is governed by the repository itself. Instead of everyone writing loose prompts in a chat, the team defines how to work with AI in versioned files that can be reviewed like code.

Why this matters

The workflow becomes repeatable, traceable, and controllable. Commands standardise how work starts, agents limit who does what, skills carry project knowledge, and MCPs provide governed data access instead of invented context.

Commands
Repeatable workflows

Prompt templates invoked with /name. They standardise tasks such as investigate, plan, implement, and review.

Where: .opencode/commands/<name>.md. Examples: /workshop-analyze-demo-portfolio, /workshop-plan-backend-card, /workshop-implement-frontend-slice.

Agents
Specialists with permissions

Role-specific workers with their own prompt and permissions. A backend agent can edit backend code; a safety reviewer can stay read-only.

Where: .opencode/agents/<name>.md plus root rules in AGENTS.md. Examples: backend-nestjs-agent, frontend-angular-agent, financial-safety-reviewer.

Skills
Reusable knowledge

Project best-practice manuals loaded only when the task needs them. They prevent the agent from reinventing repo patterns.

Where: .opencode/skills/<name>/SKILL.md. Examples: ghostfolio-domain-analysis, nestjs-api-development, angular-nx-development.

MCPs
Governed data access

Standard connectors that expose external tools or data to OpenCode. The workshop MCP gives read-only access to real demo portfolio data.

Where: configured in opencode.json, implemented in tools/mcp/ghostfolio-demo-data-mcp/. Examples: get_demo_portfolio_summary, detect_demo_anomalies.

Show live

Open .opencode/commands/, .opencode/agents/, .opencode/skills/, and opencode.json so participants see that the AI workflow is versioned in the repo.

Governance point

Per-agent permissions and repository rules are real control mechanisms: the AI cannot do more than the workspace allows, and the shared rules protect secrets, real data, and financial-safety boundaries.

Setup and pre-flight

Start with Getting Started if Ghostfolio is not already running.

Start Ghostfolio
bash 
./scripts/start.sh
./scripts/check.sh

Windows: use .\scripts\start.ps1 and .\scripts\check.ps1.

Seed demo data
bash 
./scripts/seed-workshop-data.sh

Create the first admin user in the UI, save the security token, then seed the three demo accounts.

Verify MCP
bash 
./scripts/check-demo-mcp.sh

The MCP insights demo can run even if Ghostfolio is not running because it reads CSV files.

Rebuild app changes
bash 
./scripts/rebuild.sh

Use this only after changing Ghostfolio app code under apps/. OpenCode config and MCP edits do not need rebuild.

Everyone checks
  • OpenCode installed and an AI model configured.
  • Docker Desktop running and Ghostfolio responding.
  • Demo data loaded with seed-workshop-data.
  • MCP green with check-demo-mcp.
  • Repo opened at the root so OpenCode detects opencode.json.

8
Guardrails and done checklist
Do not touch
  • No .env, .env.dev, .env.example, or secrets.
  • No real user data. Use only the demo dataset.
  • No prisma/schema.prisma, migrations, Docker files, nx.json, or tsconfig.base.json.
  • No personalised financial advice. Describe, do not advise.
  • No git commit or git push unless the facilitator asks.
Card done
  • Functional objective met with a plan or minimal code.
  • At least one command, agent, skill, or MCP was created, improved, or used.
  • Visible text passes /workshop-review-financial-safety.
  • git status and git diff reviewed.
  • Handoff prepared with /workshop-prepare-team-handoff.
Safety wording

Insights should be descriptive and educational. Avoid instructions such as buy, sell, rebalance now, increase exposure, or reduce this position.
